# ShipSafe — Release Guardian

A **real full-stack starter application** for evidence-based Git change analysis, extended with a **human-mediated Claude Code review handoff**.

- **React + TypeScript + Vite:** modern, responsive engineering dashboard
- **FastAPI + Python AST + Git CLI:** examines real diffs between commits
- **SQLite:** saves scan reports for later inspection
- **Synthetic LedgerLite repository:** creates six demo branches with intentional and harmless changes
- **pytest:** executable backend acceptance tests
- **Claude Code handoff (no API key in ShipSafe):** export exact scan evidence, review using your signed-in Claude Code account, validate/import structured findings
- **Separate AI review history:** imported suggestions stored in SQLite without changing static findings or test execution status

**No AI API key or client credentials required for ShipSafe.** The manual Claude Code step requires your own authorized Claude Code installation and subscription access. No production access is required.

## Quick start

Prerequisites: Python 3.11+, Git, and **Node.js 22.12 or newer in the 22 line, or Node.js 24 or newer**, with npm. Node 20 is no longer supported for the frontend: the test runner (Vitest 5) requires Node 22.12+, and `frontend/package.json` declares this in `engines`.

### 1. Install backend dependencies

```bash
# from the repository root
python -m venv .venv
# macOS/Linux:
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r backend/requirements.txt
```

### 2. Install frontend dependencies

```bash
cd frontend
npm install
cd ..
```

For an exact, reproducible install use `npm ci` instead of `npm install`. Frontend checks, run from `frontend`: `npm test` (Vitest with Testing Library, in jsdom; no backend needed) and `npm run build`. `npm run dev:mock` starts the dashboard with invented Bitbucket data (development server only, permanent MOCK DATA banner, no request to Bitbucket) so the Bitbucket screens can be looked at without a credential.

### 3. Start both applications

```bash
python scripts/dev.py
```

Open the **dashboard** at http://127.0.0.1:5173 and FastAPI **Swagger API docs** at http://127.0.0.1:8000/docs.

The backend automatically creates `backend/demo-repo/` and its Git history on first launch. The dashboard automatically loads a real scan of `main` vs. `feature/release-candidate`. Select another branch and click **Run analysis** to create a new scan.

> If you prefer two terminals, run `cd backend && python -m uvicorn app.main:app --reload --port 8000` and `cd frontend && npm run dev` separately.

## NEW: Claude Code Team handoff — without an API key

This is intentionally a **manual, developer-controlled** bridge. ShipSafe does **not** call Anthropic APIs, log in on your behalf, execute `claude`, proxy a subscription session, or store session tokens. Each reviewer signs in with their own authorized Claude Code account. See [Claude Code setup](https://code.claude.com/docs/en/setup) and [legal and compliance](https://code.claude.com/docs/en/legal-and-compliance).

1. Start ShipSafe. Run a scan, or use the default synthetic `feature/release-candidate` scan.
2. In the left sidebar, open **Claude Review**.
3. Click **Download handoff ZIP**. The archive includes:
   - `review-input.json`: scan ID and SHA-256 context digest, **actual** Git diffs, static findings, and test suggestions.
   - `REVIEW_INSTRUCTIONS.md`: detailed review task and required trust boundaries.
   - `response-template.json`: strict output fields, with placeholders that Claude must replace.
4. Extract the ZIP into a new local folder, then in a terminal:

   ```bash
   cd path/to/extracted-handoff-folder
   claude
   ```

5. Authenticate via the official Claude Code UI with your Team account if asked. Paste:

   ```text
   Read REVIEW_INSTRUCTIONS.md and review-input.json in this directory.
   Follow the instructions and write claude-review.json.
   Do not run code or modify any other files.
   ```

6. Review the generated `claude-review.json` yourself. Return to ShipSafe → **Claude Review**, choose the JSON file, and click **Import review**.
7. The dashboard displays the imported summary, release recommendation, suggested findings, proposed regression tests, and limitations. Your earlier Git risk score and static findings stay unchanged.

### Contract and safety

The importer refuses malformed JSON, unsupported fields, oversized files (>256 KiB), the wrong scan ID or SHA-256 context digest, references to files not changed in that scan, and unknown static finding IDs. It stores timestamped imports separately. It cannot verify that Claude authored the document, that evidence claims are true, or that suggested tests were executed. Every import is visibly labeled **unverified**.

**Review the package before sharing it with Claude.** The ZIP contains code diffs and may include proprietary information if you opted in to scanning a non-demo repository. Use the synthetic demo repository by default and respect your organization's policies.

You can also use the endpoints directly:

```bash
# Download ZIP containing instructions, Git evidence and JSON response template
curl -L http://127.0.0.1:8000/api/scans/SCAN_ID/ai/handoff -o handoff.zip

# Import an output generated in your own Claude Code session
curl -X POST http://127.0.0.1:8000/api/scans/SCAN_ID/ai/reviews \
  -H 'Content-Type: application/json' --data-binary @claude-review.json

# Read the latest imported result
curl http://127.0.0.1:8000/api/scans/SCAN_ID/ai/reviews/latest
```

This is a local development tool. Do not expose its API publicly without appropriate authentication and access controls.

## Run the tests

```bash
cd backend
python -m pytest -q
```

The supplied backend tests verify generated branches, risk scanning, path allowlisting, JSON export, end-to-end handoff ZIP creation, structured review import/history, and rejection of wrong-scan, fabricated test-result and malformed inputs.

The separate synthetic LedgerLite fixture includes **deliberately incomplete happy-path tests**. If you choose to inspect them manually, first generate the repo, then run:

```bash
python scripts/seed_demo.py
cd backend/demo-repo
python -m pytest -q
```

Do not confuse these deliberately incomplete smoke tests with proof of correctness.

## Scan your own authorized local repository

The backend starts in a **deny-by-default** mode: it scans only the generated synthetic demo repository. To explicitly authorize another directory (never a client or production repo without permission):

```bash
export SHIPSAFE_ALLOWED_ROOT=/absolute/path/to/trusted/workspace
```

Restart the API, then POST to `/api/scans` with `repository_path`, `base_ref`, and `head_ref`. The repository must be inside that explicitly permitted directory. For Windows, use `$env:SHIPSAFE_ALLOWED_ROOT = 'C:\path\to\trusted\workspace'`.

The synthetic demo repository stays scannable alongside an authorized directory. A drive or filesystem root is refused at startup.

To change the SQLite database path, set `SHIPSAFE_DB_PATH`. To change where demo files are generated, set `SHIPSAFE_DEMO_DIR`. These can also go in a root `.env` file (copy `.env.example`), which `python scripts/dev.py` loads.

Full settings reference: [docs/CONFIGURATION.md](docs/CONFIGURATION.md). Components, API, and security boundaries: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Architecture

```text
React dashboard (localhost:5173)
  │   branches, scan actions, report navigation, Git patches, exports
  ▼
Vite /api proxy
  ▼
FastAPI (localhost:8000)
  ├── git diff / git show / git ls-tree — read-only comparisons
  ├── Python AST — changed functions and direct importers
  ├── Risk heuristics — security, pricing, API contract
  ├── SQLite — scan history / evidence
  ├── Manual Claude handoff — ZIP export, strict JSON import, no authentication tokens
  └── Synthetic Git fixture — real commits and branches
```

The score is a **simple heuristic prioritization number**, not an empirically calibrated probability of failure. Every finding is tagged `suspected`. A release is never declared safe based on the scanner alone.

## Current limitations (important)

This is a **working foundation**, not a production-ready security platform:

- No repository test execution through the API or dashboard (avoids running arbitrary source code).
- AI review has two paths: the API server can send a scan to **OpenAI or Gemini** when that provider's key is set on the server (`docs/CONFIGURATION.md`), or you review it in your own **Claude Code** session and import the JSON. ShipSafe never calls Claude directly. All AI output is stored as unverified suggestions: it does not change the static findings count, the risk score, or test status. There is no patch application, GitHub/GitLab OAuth, or CI gating.
- **Static risk rules are Python-only and cover three patterns.** They read `.py` files only and flag: a removed permission or ownership check, Decimal money arithmetic replaced by float, and keys removed from an API response. Files in any other language (JavaScript, TypeScript, Kotlin, Java, Dart, …) are not analysed, and other kinds of bugs are not looked for. **0 suspected risks is not proof that a change or repository is safe**; for non-Python code it usually only means the rules did not apply. The dashboard says how many changed files the rules did not analyse; use an AI review and human review for those. Existing-test discovery reads Python (pytest `test_*.py` / `*_test.py`) and Dart/Flutter (`*_test.dart`, matched through relative or `package:` imports using the repository's `pubspec.yaml`) test files; "affected importers" counts direct Python imports only. Test proposals accept Python (pytest) files only, and Run is available only for the synthetic demo repository (where it is recorded as BLOCKED).
- QC test cases (Test intelligence page) are written by an AI model from an AI review's findings and executed by people; ShipSafe records what testers report and never runs them. They are unverified AI text, and tester names are not authenticated.
- Test execution: a test proposal can be approved and Run can be pressed, but every run is recorded as **BLOCKED** because no verified isolated runner exists. No repository code is executed, so there is never a pass/fail result.
- Import mapping observes direct imports, not dynamic/runtime dependency flow.
- Diff previews are limited to 140 lines per changed file and 300 changed files per scan; the report, the dashboard, and the handoff ZIP flag when either limit was hit (`summary.truncated`, `files_omitted`, per-file `diff_truncated`). Large repositories need pagination.
- Local SQLite is single-machine storage. There is no multi-user authentication or role-based access. An imported JSON author cannot be independently attested.
- Do **not** expose the FastAPI service publicly without authentication, rate limits, and stronger repository isolation.
